Enables Storybook's additional features.

## `actions`

Type: `boolean`

Default: `true`

Enable the [Actions](../../essentials/actions.mdx) feature.

> **Renderer: `angular`**

## `angularFilterNonInputControls`

Type: `boolean`

Filter non-input controls in Angular.

On `@storybook/angular-vite` this feature is deprecated in favor of the [`propsTable` framework option](../../get-started/frameworks/angular-vite.mdx#propstable): `true` maps to `propsTable: 'inputs'` and `false` maps to `propsTable: 'all'`.
The option's third value, `'api'`, needs the [`docgenServer`](#docgenserver) feature.
Setting both leaves `propsTable` in charge.
`@storybook/angular` still reads this feature and is unaffected.



## `argTypeTargetsV7`

(⚠️ **Experimental**)

Type: `boolean`

Default: `true`

Filter args with a "target" on the type from the render function.

> Code snippet: `_snippets/main-config-features-arg-type-targets-v7.md`

## `babelRemoveBugfixes`

(⚠️ **Webpack builder only**)

Type: `boolean`

Disable the `bugfixes` option in `@babel/preset-env` for Webpack builder. This option was removed in Babel 8 and now causes Babel to throw an error. Set this to `true` if you use Babel 8 and Storybook fails to detect your Babel version.

## `backgrounds`

Type: `boolean`

Default: `true`

Enable the [Backgrounds](../../essentials/backgrounds.mdx) feature.

## `changeDetection`

Type: `boolean`

Default: `true`

Enable [change detection](../../configure/user-interface/change-detection.mdx). When enabled, Storybook monitors your git working tree and the builder's module graph to show which stories are new, modified, or related to code changes. Changed stories are displayed with status icons in the sidebar.

[Agentic review](../../ai/agentic-review.mdx) builds on change detection, so disabling this feature also disables review.

## `componentsManifest`

Type: `boolean`

Default: `false`

Generate [manifests](../../ai/manifests.mdx), used by the [MCP server](../../ai/mcp/overview.mdx).



> **Renderer: `react`**

With the default [`docgenServer`](#docgenserver), manifests use a ref-based format with per-component JSON snapshots for faster MCP loading.



> **Renderer: `angular`**

Manifests are generated by [`@storybook/angular-vite`](../../get-started/frameworks/angular-vite.mdx), which reads your component API from your TypeScript sources with the default [`docgenServer`](#docgenserver).
The Webpack-based `@storybook/angular` does not generate manifests, and setting this feature there has no effect.



> **Renderer: `vue`**

Manifests are generated by `@storybook/vue3-vite` and require [`docgenServer`](#docgenserver), which is enabled by default.
Other Vue setups, including `@nuxtjs/storybook`, do not generate manifests.



> Code snippet: `_snippets/main-config-features-components-manifest.md`

## `experimentalCodeExamples`

(⚠️ **Experimental**)

Type: `boolean`

Prefer [`docgenServer`](#docgenserver), which supersedes this flag and provides the same static snippet behavior along with faster, more accurate docgen.

Enable the new code example generation method for React components (as seen in the story previews in an [autodocs](../../writing-docs/autodocs.mdx) page).

Unlike the current implementation, this method reads the actual stories source file, which is faster to generate, more readable, and more accurate. However, they are not dynamic: they won't update if you change values in the Controls table.

> Code snippet: `_snippets/main-config-features-experimental-code-examples.md`



> **Renderer: `['react','angular','vue','web-components']`**

## `docgenServer`

Type: `boolean`

Default: `true` when the framework ships a server-side docgen provider: every React and Vue 3 framework, `@storybook/angular-vite`, and `@storybook/web-components-vite`. `false` otherwise.

React and Vue 3 extract component metadata with TypeScript, so for them the default is only `true` when the `typescript` package is installed. A JavaScript project without it keeps builder docgen.

Enable server-side docgen. Storybook extracts component metadata on the dev server using the TypeScript Language Service instead of injecting docgen into the preview bundle. This provides faster startup, more accurate [Controls](../../essentials/controls.mdx) and ArgTypes tables in [autodocs](../../writing-docs/autodocs.mdx), and improved static code snippets in docs and the Code panel. [Manifests](../../ai/manifests.mdx) and the [MCP server](../../ai/mcp/overview.mdx) use an optimized, ref-based format that loads faster for AI agents.

Snippets are static: they won't update if you change values in the Controls table.



> **Renderer: `react`**

When enabled, you do not need [`experimentalCodeExamples`](#experimentalcodeexamples) because snippet generation is handled by the server-side story-docs service.



> **Renderer: `['react','angular','vue','web-components']`**

To use the legacy builder-based docgen path, turn the server off:

> Code snippet: `_snippets/main-config-features-docgen-server.md`

Server-side docgen replaces React's `typescript.reactDocgen` and Vue's `framework.options.docgen`.
There is no translation for `reactDocgenTypescriptOptions`, including `propFilter`, or for a custom Vue docgen `tsconfig`.
Set `docgenServer: false` if your project depends on those settings.

On `@storybook/angular-vite`, `framework.options.compodoc: false` only prevents Compodoc from running on the legacy path. It does not turn off `docgenServer`; use the feature option for that.



> **Renderer: `react`**
